项目背景Context

真实的应付审核痛点，落到 ERP 里解决A real AP review problem, solved inside the ERP

不是做一个独立网页工具，而是在 Odoo 的模型、菜单、权限和报表体系里完成整条实施链路。Not a standalone web tool: the whole implementation chain runs on Odoo models, menus, access rights and reports.

01

痛点Problem

月结前人工核对供应商、发票号、金额和会计期间；重复发票、借贷不平、字段缺失靠人眼发现，效率低且容易漏。Before month-end close, supplier, invoice number, amount and period are checked by hand. Duplicates, unbalanced entries and missing fields are found by eye — slow and easy to miss.

02

做法Approach

把审核经验拆成 9 类、10 条可配置规则；在 Odoo 里完成导入、校验、异常跟踪和看板分析，业务改阈值不需要改代码。Review know-how becomes 10 configurable rules across 9 types. Import, validation, exception tracking and dashboards live in Odoo; changing a threshold needs no code change.

03

结果Outcome

样例 36 行自动识别出 20 行异常、5 行警告；异常附带中文差异说明，业务人员可以直接回到凭证修改。From 36 sample lines, the module flags 20 failures and 5 warnings. Each anomaly carries a plain-language difference note the business can act on.

业务规则先行，代码其次。Business rules first, code second. 规则存在数据模型里，校验器只读取启用规则执行。Rules live in the data model; the validator simply reads the active ones and executes them.

功能范围Scope

从导入到文档，一条完整链路One complete chain, from import to documentation

全部功能都落在 Odoo 原生模型和视图里：list、form、search、graph、pivot、QWeb 报表和权限组。Everything uses native Odoo models and views: list, form, search, graph, pivot, QWeb reports and access groups.

01

规则配置Configurable rules

规则类型、异常级别、阈值、费用类型、允许科目和供应商黑名单均可维护；没有写死在代码里。Rule type, severity, threshold, expense type, allowed accounts and supplier blacklist are all maintained in the UI, not hard-coded.

02

Excel / CSV 导入Bulk import

复用 Odoo base_import 解析 xlsx / csv / ods，中文表头自动映射，空行自动跳过。Reuses Odoo base_import for xlsx / csv / ods, maps Chinese headers automatically and skips empty rows.

03

9 类自动校验9 validation types

借贷平衡、重复发票、金额符号、期间逻辑、必填字段、科目合规、报销限额、供应商黑名单、审批层级。Balance, duplicate invoices, amount signs, period logic, required fields, account compliance, expense limits, supplier blacklist and approval level.

04

异常清单与批次汇总Exceptions and batch summary

异常码、中文差异说明、批次通过率、异常分布；支持按结果分组、筛选和跳转明细。Anomaly codes, plain-language notes, pass rate and anomaly distribution, with grouping, filters and drill-down to lines.

05

分析看板Analysis views

Odoo 原生 graph + pivot + list，按结果、异常类型、期间、月份和批次下钻。Native graph, pivot and list views, drilled down by result, anomaly type, period, month and batch.

06

文档自动生成Generated documents

QWeb + wkhtmltopdf 生成业务需求文档和用户操作手册；规则变了，重新打印即可。QWeb and wkhtmltopdf generate the business requirements document and user manual; reprint when rules change.

真实性边界Scope and honesty

这是 Odoo 19 上的个人实践项目，模拟 SAP FI 应付凭证校验场景；不是 SAP 系统操作，不是生产上线。This is a personal practice project on Odoo 19, simulating an SAP FI AP voucher validation scenario. It is not SAP system operation and not a production rollout.

不含 OCR、真实客户数据或真实 LLM API 调用；样例供应商、金额、发票号均为合成数据。演示账号与本地数据库口令仅用于本机环境。No OCR, no real customer data and no live LLM API calls. Suppliers, amounts and invoice numbers are synthetic. The demo login and local database credentials are for the local machine only.
